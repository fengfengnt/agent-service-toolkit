# 多份 Skill 的指令冲突处理

Labels: wayfinder:grilling
Type: grilling
Status: resolved
Assignee: 当前对话（标准 Skill 与 DeepAgents 接入设计）
Blocked by: 02

## Question

同一节点中两份可用 Skill 的说明或流程要求冲突时，如何确定当前流程及辅助材料的职责，何时拒绝启用、要求调整绑定或向用户澄清，避免模型自行拼接出未定义的流程？

## Context

本票讨论的方案：

- 系统的权限、草稿字段规则、提交条件及真实业务结果为执行约束，任何 Skill 都不能改写。
- 当前留资 Skill 负责该草稿的引导；辅助 Skill 可提供解释和分析，不改变当前流程的必填、保存与提交条件。
- 可验证的绑定、依赖或配置冲突在启用前处理；两份同职责 Skill 无法确定执行归属时，交由维护者修正绑定或说明，不让业务用户替系统裁定。
- 用户意图确实不明确时才向用户澄清；运行中无法判定的技能冲突暂停受影响动作，保留草稿，不自行混合冲突规则。
- 不承诺自动识别所有自然语言说明冲突；可验证的约束靠程序检查，语义行为通过评测与运行记录验证。

## Answer

2026-11-11，用户对上述多份 Skill 的冲突处理规则回答“是”。

- 系统权限、草稿字段规则、提交条件和真实结果保持有效，Skill 不能改写。
- 当前留资 Skill 推进草稿流程，辅助 Skill 不改变该草稿的保存与提交条件。
- 配置冲突交由维护者修正，不让业务用户裁定内部技能绑定；用户意图不清时才澄清。
- 运行中无法判定冲突时，暂停受影响动作并保留草稿，不自行混合互相矛盾的规则。
- 自然语言冲突识别不作为绝对保证，设计需包含可验证约束及语义评测。
