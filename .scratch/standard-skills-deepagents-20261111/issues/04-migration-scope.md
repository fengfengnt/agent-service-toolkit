## Question

首版迁移哪些业务节点、三份留资 Skill 和现有答疑材料；subagent 首版做到可配置接入和验证，还是落地具体业务子任务，如何与正在进行的留资实现协调及验收？

## Context

2026-11-11 本地只读核对：现有答疑 SKILL.md 共 18 份，留资 SKILL.md 共 3 份；最近提交 e19cac7 已包含留资设计实施与验证记录。该事实不等于本聊天复验了留资功能。

本票讨论的首版范围：

- 四个业务 Agent 统一接入 DeepAgents，按节点职责配置模型决策与技能使用，继续复用现有业务工具及确定性校验。
- 将三份留资及十八份现有答疑资源迁移为标准 Skill，保留已有业务内容与事实边界；接待 Agent 不因接入而自动获得专业方向权限。
- 前端按服务端输出展示已有字段组成的 form；涉及接口和界面的适配纳入设计，不要求仅编辑 Skill 即完成所有改造。
- subagent 首版支持显式配置 Skill、只读工具与结果返回，并以隔离测试验证；暂不新增正式生产业务子任务或跨轮长任务。
- 以已提交的留资实现为迁移基线，保留其字段、确认、版本及幂等行为。
- 本轮仍仅形成设计，不开始产品代码、安装、迁移或部署。

## Answer

2026-11-11，用户明确同意首版按上述范围设计，要求继续完善设计文档、暂时不要写代码，并询问接入后 workflow 能否精简。

首版包含四个业务 Agent 的 DeepAgents 接入、三份留资与十八份答疑 Skill 标准化、必要的前后端适配、自定义只读 subagent 的配置及隔离验证。具体生产子任务、跨轮长任务和子任务专用前端进度不纳入首版。

设计需说明哪些现有流程节点可收敛为 Skill 驱动的业务节点，哪些权限、数据写入、幂等与恢复职责继续由程序落实；不能把 workflow 节点减少等同于删除业务约束。
