# 2026-11-06 转化入口与本地认证修复

## 用户反馈与原因

- “合作怎么付费”“多少钱”未触发转化：共享流程及三个答疑路由漏掉“付费”“多少钱”。
- 转化邀请没有可点击入口：原实现需要用户先输入完整接受语，再显示注册登录按钮。
- 点击按钮显示“小鹤服务暂不可用”：本地实际 SSO 的 `sso_bridge_application` 未登记配置中的应用，中心返回 `401 / 1002029021`，AI 将其安全映射为 `503 / UPSTREAM_UNAVAILABLE`。
- 真实页面中回复文字可先于 Run 完成事件显示；此时立即点击并发送接受语会收到 `RUN_ACTIVE`。认证按钮现在等待当前回复完成后启用，访客额度不足仍可使用认证入口。

## 最终行为

1. 三方向询价等转化信号：先专业答疑，附邀请文字及“注册或登录”按钮；出现邀请本身不办理认证、不建立正式申请。
2. 点击按钮视为主动接受邀请。前端沿用原 Native 对话入口发送“我愿意登记需求”，收到服务端接受回执后自动展开认证卡片，一次点击即可进入手机号表单。
3. 用户也可以在当前邀请后回答“是／是的／好／好的／可以”。没有当前邀请时，这类短答不视为登记同意。
4. 暂缓后不再次催促；用户明确要求登记或主动点击入口后继续。
5. 社群组织“预约方案沟通／观看样板演示／索取合作手册／开始入驻”的前置登记入口使用相同行为，保留暂缓状态。
6. 手机号、验证码、协议与登录回跳继续走已有认证流程，不进入 AI 对话。登录与资料最终确认仍是不同操作。

## 后续反馈：连接指示与登录回调

- `copilot-session.ts` 原先把正常空闲短流结束后的控制面轮询，反复标为 `loading/connecting`。现在正常轮询保留已验证的在线状态，首次连接和实际失败后的恢复仍显示连接过程，实际网络失败仍进入断线状态。`XiaoheWidget.vue` 等待用户输入时不再显示任务处理中。
- `AuthCard.vue` 在手机号验证成功及必要的主动协议确认后，自动移交既有浏览器认证完成流程。移除了额外“继续完成登录”按钮，显示“正在完成登录，请稍候…”，没有省略服务端身份验证、协议、账号切换决定、OIDC 校验或 AI 账户绑定。
- 空白回调在本地专用窗口中复现：原 Playwright 请求改写在跨源重定向后没有覆盖门户 callback，请求落到原部署，页面空白。直接访问合成错误 callback 时新版页能正常显示，证明不是简单缺少 callback 页面。
- 专用窗口启动器改为浏览器进程级 `--host-resolver-rules` hostname/port 映射。门户 Origin、Cookie 与已登记回调保持不变，SSO 请求仍访问实际认证中心；严格 TLS 校验保留，不改共享 Nginx或系统 hosts。必须新开测试窗口以应用该进程参数。
- 实测发现宿主系统代理会绕过上述地址映射，曾连接代理后落到旧业务。仅为专用测试浏览器追加 `--no-proxy-server`，不修改全局代理。启动器核对 `response.serverAddr().port === 18116`；回归同时核对新版固定欢迎语、Native开场与注册接口，避免只因页面可显示就误认实例正确。
- 自动登录的测试调用方同步取消手工点按钮；草稿并发更新的布置移到手机号验证前，继续检验登录前未保存内容与较新正式资料的恢复边界。
- 验证不使用用户提供的一次性授权码；真实账号再次登录、短信及正式留资仍由用户手工验收。
- 本轮验证：342项单元测试、36项安全检查、12项认证卡片浏览器检查、24项完整认证与接待浏览器回归通过，类型检查和构建通过。实际独立网关的跨源重定向回调可见、7秒空闲状态只出现首次连接后在线、新版Native采购商开场与注册接口201通过；真实短信留给用户测试。
