# 小鹤共享官方知识设计

日期：2026-11-16。状态：用户已批准并定稿，后续已授权本会话 Native 实施；尚未授权本次功能部署。

已完成一次独立可实施性检查，无新增必须澄清的问题；这不代表产品代码、运行环境或业务验收已经完成。

## 1. 目标与范围

一份官方知识统一维护，接待、采购、社群组织、供应四个业务 Agent 及通过统一工厂创建的 subagent 默认获得完整内容；同一源文件支持离线向量索引。默认知道指资料始终存在于本轮模型上下文，并非承诺模型永不出错或每句回答都重复介绍。

仅覆盖小鹤运行链路，不改变 Toolkit 其他示例 Agent、独立小采或客户环境。保留标准 Skills / DeepAgents；不把共享事实包装成可选 Skill，不恢复旧目录或 DSL。暂不新增管理界面、网页抓取、热更新、多租户品牌切换或自动索引清理。

## 2. Approaches 与已确认选择

| 方案 | 取舍 | 决定 |
| --- | --- | --- |
| 整份共享资料默认加载，同源内容可构建向量索引 | 简单、检索故障时仍可回答基础事实；需控制文档长度 | 用户已选择，首版采用 |
| 核心事实默认加载，长篇说明按需检索 | 适合资料较多时，但需区分必知部分和详细资料 | 留待确有增长需求时讨论，首版不实施 |

只依赖向量命中或模型自行读取可选 Skill，均不能满足所有业务 Agent 默认获得资料的要求。

## 3. 单一知识源

固定路径 `resources/xiaohe/knowledge/platform-common.md`，稳定文档 ID 为 `platform-common`。使用既有知识源 Markdown front matter：`id`、`title`、`source`、`conditions`、`agents`、`topics`；显式授权四个业务 Agent，主题为 `general`，不新增一套元数据协议。

正文包含：平台名称；公司全称；审定的公司简介与官方链接；“七天极速上线”定义、适用条件与边界；“1v1专属方案”内容、适用条件与边界。两项服务由用户后补，目前明确标记待补充，不推测价格、时效、交付物或无条件保证。未确认正式链接时不编造地址。

名称、简介和服务口径只在该文件维护。初稿可参考门户现有公开资料，但不能将网页中的宣传自动提升为经用户审定的交付承诺。链接作为可展示的出处，不在每轮访问网页或让网页内容绕过版本发布。

首版正文上限为 UTF-8 8 KiB；超限拒绝发布，不截断。该上限为设计阶段作者提出、随设计获批的取值。既有路径、编码、重复 ID、YAML 和文件大小安全校验继续保留。正文仅包含公开事实；不得放密钥、用户资料或工具操作指令。

## 4. 加载、权限与回答

新资源包发布时校验并载入完整共享源文件到 `RuntimeBundle.resources`，正文与元数据均参与资源包摘要。主 Agent 与只读子 Agent 的模型装配都使用该资源包的已解析正文；不依赖用户提问、登录状态、已选 Skill 或是否命中向量检索。

共享资料作为明确标注的数据放入上下文，执行约束仍由系统规则、角色绑定、标准 Skill 和受控工具决定。子 Agent 仅增加这份公开知识，不继承父 Agent 对话、用户身份、文件或写工具；现有只读边界保持。后续新增业务 Agent/subagent 必须经过统一装配入口并验证共享资料可见；向量授权仍需按新角色显式登记。

相关问题依据共享资料回答，不要求每轮介绍公司或附免责声明。共享事实有稳定且可校验的内部来源 ID，关闭向量检索时也能合法引用；沿用现有回答来源校验，拒绝模型伪造其他来源。首版不改变对客消息协议，不强制为每次普通回答增加来源尾句；用户问出处时可提供审定官方链接。

现有接待资料与各 Skill 中重复的平台事实应改为引用共享来源。对已审定内容按其适用条件解释；未载明条件继续待确认。不能让现有“交付时间一律待确认”的概括阻止解释后续审定的服务定义，也不能让共享资料覆盖登录、保存、提交等工具回执。

## 5. 版本与同源索引一致性

同一命令、重试、交接和该命令触发的子任务使用同一 `RuntimeBundle`；新命令使用当前已发布资源包。共享知识不从运行时磁盘或全局最新版跨快照补读。

发布候选缺少共享文件、正文为空、格式或授权非法时拒绝发布，保留当前运行版本。历史命令绑定的旧 Bundle 若尚无共享文件，按原快照完成，不追写数据库或偷换新知识；下一条新命令才进入已发布的新版本。这是升级过渡边界。

同源索引使用既有构建器、Chroma、manifest 及不可变版本目录。比对当前共享文档与 manifest 中同一文档 ID 的完整分块集合、每块正文摘要及元数据，不能只比对文件名或更新时间；复用既有分块规则，不发起 Embedding 即可判定是否同源一致。

用户已确认发布规则：允许先发布新版常驻正文，再补建索引。索引尚未同步时，排除旧 manifest 中该共享文档的所有分块；其他授权知识仍可检索。若没有同步的可检索条目，不请求 Embedding。新索引发布并与正文匹配后，向量产物恢复为与正文一致的可用版本。默认常驻路径始终在 top-k 前排除该文档的全部向量条目，不让重复资料占用专业知识的召回名额；同源索引仍可构建、校验和保留。

同一源文档已默认完整载入，不再重复向模型注入其向量命中文本；保留当前快照中的正文和来源即可。若本轮授权候选只有这份已常驻文档，直接使用常驻正文，不为重复内容请求 Embedding；首版不新增问题意图分类或检索路由。已完成命令的重试缓存仍保持原快照，不能用新发布正文替换原材料。旧索引保留，不自动删除或改写。

## 6. Embedding 选择与适配

用户同意采用小采复用环境的同款模型、URL 和现有 Key。2026-11-16 已在 `39.106.42.10`（UAT 与生产复用）只读核对活动 Compose `/opt/xiaocai-uta/application.compose.json` 与 API、Kernel、Worker 的生效配置：APIPro，`https://api.wenwen-ai.com/v1`，`text-embedding-3-small`，1024 维。专用 Embedding Key 为空，APIPro Key 已配置；先前配置检查与最小 API 请求未输出或复制 Key。

该环境中一次公开英文短文本请求显式传入 `dimensions=1024`，返回 1024 维、有限且非零向量；耗时约 1.49 秒，输入 5 tokens。只证明该次接口响应和维度可用，不证明小鹤 WSL 网络耗时、中文业务召回质量或高分位延迟。

小鹤继续使用自己的 `XIAOHE_KNOWLEDGE_EMBEDDING_*` 配置项：BASE_URL 复用上述地址，MODEL 使用 `text-embedding-3-small`，DIMENSIONS 为 1024，API_KEY 复用该实例实际有效的 APIPro Key。实施并获目标环境操作授权后，以私有通道仅传递该项凭据，不复制整份小采 `.env`，不改动小采凭据、认证或模型配置。真实 Key 不进入共享文档、计划、Git、发布包或工具输出；验证仅报告是否配置及是否一致。

两项目共用该 Key，因此配额、限流及后续轮换会相互影响；索引、存储和业务权限仍各自独立。本次代码实施不读取或写入实际 Key，留待目标环境接线。构建与查询必须使用相同模型、endpoint 和维度，并显式向兼容接口传递 `dimensions`；不能仅填写预期返回维度。服务不支持所选维度或返回错误维度时明确失败，不静默换模型或截取向量。

初始预算：在线 Embedding 请求 3 秒、整次检索 4 秒、离线建库请求 30 秒，均不自动重试；这些是设计阶段作者提出、随设计获批的初始值，需在目标环境验收，不是已验证的性能承诺。检索超时沿用既有单任务准入和回退，不排队积压；常驻共享资料继续可用。本轮授权候选只包含常驻共享文档时不额外请求 Embedding。

变更模型、endpoint 或维度必须构建新索引。两项目的索引、Chroma/Qdrant 数据、会话和权限保持独立；同款模型不意味着复用小采索引。未配置模型时共享知识仍完整加载。

## 7. 预期改动与验收

实施应限于：共享 Markdown；`deep_runtime/bundles.py` 的资源校验与快照；`deep_runtime/factory.py` 的主/子 Agent 装配；`deep_runtime/runtime.py` 的来源校验与材料去重；`knowledge/sources.py`、`knowledge/runtime.py` 的同源一致性及检索过滤；`knowledge/build.py` 的维度和超时传递；相应配置说明与有意义的回归测试。具体最小接口由实施计划确定，不修改数据库表结构或前端协议。

必须验证：

1. 四业务 Agent 的访客/登录绑定及只读子 Agent 均收到同一完整正文；无需先读取 Skill。
2. 子 Agent 保持只读且不获得父 Agent 私有上下文；用户或资料中的指令不能改变授权和工具回执。
3. 共享事实可引用合法来源，伪造来源仍被拒绝，待补充服务不会成为已确认承诺。
4. 关闭或故障的向量检索不影响共享知识；同源旧索引被排除，其他知识仍可检索，不重复注入常驻内容。
5. 正文、元数据、分块增删或空条目变化均能检出不同步；新索引与正文一致后可使用；旧命令/重试/子任务不跨版本。
6. 新资源包缺失/非法/超长共享文件时拒绝发布；历史旧 Bundle 可按原快照完成。
7. 构建与查询请求均携带所选维度，错误维度、超时、取消、后台任务未结束时的回退和准入行为符合约定。

验收分别报告源码测试、受控 Chroma、真实 Embedding、目标环境网络与业务问答结果，不能用接口 200 或一次正确维度代替全部业务验收。真实业务资料尚未补齐时只验结构与边界，不编造正式资料。
