# 小鹤仅保留标准 Skill：旧执行链与旧数据清理设计

日期：2026-11-12。状态：清理路线已由用户选择，具体执行设计待确认；本文不表示已经删除代码、数据库记录或对象文件。

## 1. 目的与决策

用户在旧目录、兼容执行链及 WSL 历史数据分析后明确要求：“旧数据无需保存，完全清理掉。”因此不再迁移旧草稿、不保留旧执行器供在途恢复。日常维护只保留二十一份标准 Skill，业务仅使用 DeepAgents 原生执行链。

本设计替代[原设计](2026-11-11-standard-skills-deepagents-design.md)中“保留旧草稿／旧执行器／旧选版回退”的要求；身份隔离、受控工具、字段校验、提交确认、真实回执、幂等及原生快照恢复要求继续有效。

## 2. Approaches

- **迁移历史资料后移除旧执行器**：保留草稿和历史布局，需要迁移和兼容验证；用户已明确不需要保留这些数据，不采用。
- **清空旧会话资料后统一原生运行时**：删除旧数据和旧运行路径，共用业务能力继续使用；采用该路线。
- **删除整个数据库或共享存储卷**：会连带影响身份、配置及其他服务，不属于旧 Skill 清理范围，不采用。

以下涉及范围边界、数据库结构与发布顺序的细节是实现提议，不表述为用户已经逐项批准。

## 3. 清理范围与边界

本次环境限定为 WSL Ubuntu 的小鹤实例，实际业务库 `xiaohe_triad_local_20261104`。源码变更限定于 toolkit 小鹤模块及相关测试、资源、文档和发布配置。不得执行其他环境数据库或整个 PostgreSQL／MinIO 卷清空。

删除当前旧会话、消息、事件及 tombstone、Run、Command、RunAttempt、会话关联 claim、接待 flow、草稿、草稿附件登记、本地提交载荷／回执、生成物及版本；一并清除这些记录对应的 checkpoint 和对象文件。旧 workflow 快照、旧策略及本轮淘汰的原生包快照不作为历史数据保留，新服务从标准资源重新发布策略和原生快照。

保留 `systems`、`users`、`projects`、身份 Session、认证上下文／操作、访客额度及认证去重记录、秘密、证书、业务后端和其他服务；聊天清理不重置访客额度。不调用正式业务后端删除企业资料、申请或会员。claim 删除后清除身份 Session 中指向这些旧合并流程的关联标记，保留身份凭据和额度计数。

不为旧会话制作迁移档案或新的业务数据导出。已有发布包、历史备份和 Git 提交不作为本次删除目标；本次是运行数据与代码清理，不是对备份和介质的安全擦除。清理回执只记录必要计数、目标标识、摘要和结果，不保存聊天内容或附件正文。

当前检查到没有原生 Run／Command。实际执行前暂停小鹤写入口及 API／Worker，重新锁定目标集合；如出现新的原生业务数据，停止当前清理批次并重新划定旧数据边界，不把新增资料一起删掉。

## 5. 源码与结构收敛

### 标准资源成为唯一配置来源

删除 `resources/xiaohe/skills/{buyer,organization,supplier}/`、`skills/catalog.json`、`lead-skills/`、旧 `workflows/`、旧执行专用 prompts／policy，以及 `legacy-bundle-v1.json`、`legacy-lead-fields-v1.json`。逐项核对调用者后删除，历史文档与历史 Alembic 文件不因含旧路径而改写。

保留 `resources/xiaohe/skills/<role-prefixed-name>/` 二十一包、`deep-runtime.yaml`、`deep-runtime/common-policy.yaml` 和 `deep-runtime/reception-policy.md`。十八份新版 `references/answer.md` 已与旧答疑正文逐字节一致，不重新改写业务内容。

### 启动、选版和业务 API 只走原生链

启动不再构建旧 AgentRegistry 或 DSL 图；新消息和业务 Agent 入口仅要求可用原生包。移除 `XIAOHE_DEEPAGENTS_ENABLED` 及旧执行器回退语义，缺少合法原生包时启动失败，不降级。

新草稿直接绑定标准包的字段策略，字段策略为非空必需项；草稿读取、保存、汇总和提交从该固定策略获得规则，不再读取 workflow 定义。独立申请修改／重新申请使用标准包与字段策略。保留现有 wire 字段 `definitionBundleId`，改为返回相应原生包 ID；前端无需配合更名。版本失效仍返回现有冲突错误并保留客户端脏输入。

删除 `legacy`／`dsl-v1` 调度、旧编译器、旧技能 catalog 读取和草稿规则回填。保留原生使用的字段模型、策略存储、状态提示、身份校验、确认证据及写栅栏等共用实现，不整目录删除 `lead_skills` 或 `agents`。将仍被原生调用的少量公共函数从旧执行器中移出，再删除无调用者的旧代码，不保留一套空壳 DSL。

去掉 manifest／SkillSpec 的 `legacy_id`，流程技能校验直接依据 `flow_skill` 及节点绑定；原生回答来源使用标准 Skill 名称。清理旧快照后按新的内容指纹重新发布，禁止修改已有不可变快照的 payload 冒充相同版本。

原生对 `save_round`／`skip_optional`／`show_summary` 等当前业务 action 的处理不能只因函数名含 legacy 就删除；先确认门户仍在消费的协议，保留其业务语义并改名消除误导。本次不移除 v1／v2 API 能力协商、单一提交入口及现有 DTO，避免无关的前端破坏性变更。

### 数据库结构

新增 Alembic `0015`，不修改已部署的 0001—0014 历史文件。迁移先检查受影响旧运行记录和旧定义引用已经清空，未满足就拒绝执行；不得在普通服务启动时自动销毁业务数据。

移除旧 workflow 定义表及对应外键、Run 的旧 workflow 绑定／运行时判别列、草稿的旧 definition 绑定列。保留原生 bundle 绑定、Command 原生执行快照、独立字段策略和引导状态；删除旧结构不等于删除原生 checkpoint／幂等机制。迁移后的模型、约束和新建路径一致，不能保留默认生成 legacy Run 的入口。

## 6. WSL 一次性清理与切换

1. 先完成代码、迁移和隔离验证，准备可核对的新镜像和清理入口；本设计不指定或擅自提升发布版本。
2. 暂停小鹤写入口和 API／Worker，重新核对数据库身份、目标数量、无新增原生记录及无跨系统附件引用，核对其他服务基线。
3. 固定会话／Run／Command／线程／job／对象 key 的私有删除清单。线程取自目标 Conversation、Run、RunAttempt 及内层执行记录；不能全表删除共享 `public.checkpoint_*`。任务只处理目标小鹤 job，不能清空共享 Procrastinate 历史。
4. 利用已有 S3 删除适配逐个清理归属明确的对象并验证不存在，先核对是否启用对象版本。遇到共享引用、版本历史或所有权不明就停止，不能只写删除标记后宣称已清空。只按 S3 key 操作，不直接删除 MinIO 数据盘文件。
5. 在受控事务中按外键依赖删除目标数据、claim 及关联标记、目标 checkpoint 和淘汰快照。普通共享认证／额度记录保留。对数据库外对象删除不能承诺事务回滚，失败时维持维护状态，依据删除清单继续核对，不自动恢复旧记录。
6. 执行 0015，启动新 API／Worker，重新发布标准包和策略。核对旧结构／旧记录已无运行依赖，原生新会话、草稿和表单可用，其他服务、身份、额度和配置保持。

已删除的聊天、草稿、附件及执行状态不恢复。数据库完成结构迁移后不能直接启动旧 0.1.7 镜像；出现应用问题应修复原生版本继续发布，不能通过盲目降库或恢复旧数据回退。实际发布还需遵守既有版本门槛，不隐含 UAT／生产发布或 Git 推送。

## 7. 验收条件

- 删除所有旧资源后启动及四业务入口可用，实际执行读取标准 `SKILL.md`／资源；没有 DSL／旧 catalog 的运行依赖。
- 采购、组织、供应商的新建、保存、缺项提示、修改、提交、结果未知核对、正式进展和独立申请表单仍使用真实工具状态；提交键和副作用去重不减弱。
- 原生包更新后已执行 Command 仍固定原快照，重试和强杀恢复不重复写入；只读 child 无新增写权限。
- 0015 在空的新安装库可升级，对未清理的旧库拒绝；清理在隔离 PostgreSQL 库及对象存储替身中验证重复执行、删除失败、共享线程／对象保留和身份配置不变。
- 更新相关测试 fixture，去掉仅证明旧执行器继续工作的测试；保留并迁移身份隔离、字段规则、外部提交、幂等及恢复等行为测试，不靠删除失败测试获得绿灯。
- WSL 验证旧会话／草稿／执行数据及目标对象已删除、新标准包及策略已发布，API 健康、Worker 心跳和严格 TLS 入口正常；真实模型、短信和正式业务写入单独记录，不以健康检查代替。

## 8. 留给实施者的决定

复用已有安全校验、对象删除和 checkpoint 删除能力；具体公共函数放置位置、外键删除顺序、fixture 组织和有限的代码搬移由实施者依据调用链确定。若实际清理范围超出本文边界或出现新增原生业务记录，先重新核对范围，不扩大删除。旧备份、Git 历史和其他业务后端数据的销毁不包含在本设计。
