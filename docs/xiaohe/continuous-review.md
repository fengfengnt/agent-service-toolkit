# P2–P7 整批独立评审与修复

评审范围为 5ee3b56..7d6af57，由一个独立上下文的只读 reviewer 完成，未分派实现代理。原结论：无 Critical，两个 Important，一个资源释放 Minor。主执行者逐项复现后在同一修复批次处理，没有重新做每阶段评审。

## 已复现并修复

1. **恢复任务提前确认成功。** 心跳失联时原 run 锁可能仍被旧进程持有；接管者原先正常 return，被框架记 succeeded，旧进程随后死亡就没有可恢复任务。现在有效 run 的锁冲突等待锁释放，框架 heartbeat 继续；终态/等待态可结束投递，授权失效或期限到达则结束业务状态，不把有效生成任务误记完成。真实框架测试保持旧锁、触发恢复和接管，再释放旧锁，验证 doing→实际执行→succeeded；另测等待中的执行截止。
2. **凭据文本进入持久记录。** 受理前现在统一拒绝可识别的 Bearer/token/Cookie/verifier/client_secret 等标准标记（含 JSON 字符串形式），与手机号/OTP检测共用入口，拒绝时消息/Command/run/event均不新增。历史消息重建图输入、动作文本及待答问题也采用安全文本，避免只在模型调用前脱敏。没有擅自改写或删除既有消息。
3. **断开时流未主动关闭。** 进一步测试确认普通 StreamingResponse 在 response.start 或 yield 后发送失败时不主动关闭迭代器，影响下载、SSE 和内部图流资源收尾；因此将此项按实际受影响路径提升处理。新增 ClosingStreamingResponse 统一受保护地关闭迭代器；下载 Body 由可显式关闭的迭代器管理，尚未开始迭代也能释放。

12 项回归在修复前全部观察失败（其中等待截止单独 RED），逐项修复后通过；完整业务、真实 MinIO 及原 client/threads 测试合计 231 项通过，19 条既有依赖警告。Ruff/Alembic 无差异检查通过。修复后再次使用正式 10 秒 heartbeat / 120 秒失联 / 30 秒扫描，硬杀 worker 后原业务 run 实测 132.00 秒恢复，低于 180 秒目标；同时验证同一输入不重复调用模型或写入人类消息。

## 保留的阶段边界

pending claim 协调归 P9；周期停止/物理清理/容量归 P10；代理、生产权限与部署归 P11。认证专用 CSRF 和 AUTH_NOT_READY 是进入 P8 前的跨工程契约补充点，见 [P8建议](integrations/p8-auth-contract-proposal.md)。这些仍未实施，不以本轮测试代表已经提供。

真实模型、SSO/短信、浏览器与生产部署没有在本聊天验收。评审和测试证明本批已覆盖路径的结果，不构成全系统没有漏洞或完成最终产品验收的声明。
