## 采购和供应链 Agent

采购和供应链 Agent 围绕从需求到采购执行的业务链路，辅助采购团队组织信息、制定策略和开展协同。它服务于采购决策和业务流程，供应商选择、预算批准、合同签署等事项仍需遵循客户授权与审批制度。

门户展示的八个业务环节为：需求梳理、需求分析、RFX策略、智能寻源、合同管理、订单管理、智能单据、全局风控。

四项重点能力如下：

1. **需求梳理**：整合内外部采购需求，识别品类、数量、规格、交付要求等关键要素，辅助分类汇总，减少信息遗漏和重复。
2. **需求分析**：结合客户已授权提供的需求、历史数据、市场信息与预算，辅助研判优先级、可行性和采购安排。
3. **RFX策略**：结合需求特点和已有模板，辅助形成信息征询、询价或方案征集等策略建议及文件内容。具体采用何种采购方式，由采购方结合制度与项目情况确定。
4. **智能寻源**：组织供应商画像，围绕采购条件筛选和比较候选供方，并辅助识别相关风险。推荐结果需要采购方进一步核验，不代替资质审查、样品验证或最终选商。

适合先沟通的信息包括采购品类、需求描述、交付区域、数量或规模、主要痛点，以及现有采购系统。预算、立项和期望时间可在客户愿意提供的范围内进一步确认。

官方介绍：[AI采购](https://www.yunhezhiyuan.com/portal/procurement)。

## 销售与客服 Agent

销售与客服 Agent 围绕客户从被发现到持续服务的过程，连接客户洞察、智能获客、需求匹配、智能接待、商机转化和售后服务六个环节。

- **客户洞察**：通过对企业产品与已有客户信息的分析，辅助形成客户画像、需求标签与业务判断依据。
- **智能获客**：结合客户画像与业务策略，辅助识别和触达适合的潜在客户；触达渠道、账号和客户数据须具备合法使用条件。
- **需求匹配**：将企业产品、服务能力与客户需求进行对应，辅助推荐相关内容并组织线索。
- **智能接待**：回答有知识依据的常见咨询，辅助梳理需求，对复杂、高意向或需要人工判断的问题进行衔接。
- **商机转化**：沉淀需求与沟通信息，支持销售团队进一步评估、沟通和跟进。
- **售后服务**：围绕已确认的知识、流程和权限，辅助响应常见问题与服务诉求。

门户介绍的“7×24小时响应”指智能接待场景的能力方向，不代表人工团队全天在线，也不等于对所有请求承诺固定响应时间、解决时限或成交结果。

## Agent 场景创新

Agent 场景创新面向企业个性化痛点和非标场景，结合企业知识、业务流程与商业模式开展智能体设计、搭建和落地。

适合的起点是一个可以明确说明输入、处理步骤和预期产出的业务问题，例如咨询接待、资料整理、业务协同或已有流程的智能辅助。具体场景是否适合实施，应先确认业务规则、数据条件、授权边界和验收方式。

企业无需先把全部业务重新建设一遍，可以讨论从范围清楚的场景试点。试点规模、扩展路径、费用与交付安排均需确认，不将所有非标开发默认纳入标准交付或七天上线范围。

## 企业级数据服务

企业级数据服务为智能体与业务应用提供数据基础，主要覆盖数据归集、清洗治理、资产化管理和可视化分析，帮助企业减少数据孤岛、改善信息质量和业务可用性。

数据服务可以与智能体建设配合：先明确哪些数据可以使用、由谁维护、需要怎样更新，再组织成适合查询、分析或问答的业务知识。资料数量多不等于知识质量高；来源可靠、内容准确、权限明确和更新及时同样重要。

数据整理、知识库建设与从零训练基础大模型属于不同工作。使用“训练企业智能体”这一业务表达时，不应自动解释为一定包含模型微调、专属基础模型或某种算法训练方式。

具体数据接入、存储、模型处理、权限和交付范围需通过项目方案确认；本文件没有提供已取得的安全认证清单或数据驻留承诺。

## 企业供需增强 API 与系统集成

企业供需增强 API 将采购和供应链 Agent、销售与客服 Agent 的相关业务能力及生态能力，以 API 方式接入企业现有业务系统。门户介绍的典型承接系统包括 ERP、CRM。

与通用模型 API 相比，供需增强 API 更侧重具体业务场景中的需求分析、供需匹配、业务信息组织与协同能力。某项能力能否直接调用、需要哪些数据以及是否涉及业务写入，应以实际接口说明与授权方案为准。

客户已有 ERP、CRM、SRM 等系统时，可以先说明系统名称与版本、希望接入的环节、可用接口、数据与审批边界，再评估集成方式。两份接待方案列出的具体厂商系统属于需要覆盖和评估的问题，不表示已经具备全部现成连接器。

不能在没有技术核实的情况下承诺“任何系统零改造接入”“无需授权即可读取数据”或“所有业务操作可全自动执行”。

## A2A 与供需协作

A2A 在本文件中指智能体之间的连接与协作。对客户而言，其价值是让需求方更容易表达需求，让供给方的能力更容易被理解，再辅助双方发现适合进一步沟通的机会。

它不等于不经授权就可以交换企业机密，也不默认授权智能体代表企业签约、付款、确认交期或作出最终报价。具体共享哪些信息、是否可以自动应答、何时需要人工确认，应由参与方的授权和业务规则确定。

本次资料没有提供可对外发布的统一匹配算法、固定打分权重或商机数量保证。接待方案中的算法与候选池描述不能直接作为已上线规则对外宣称。

1. **初步咨询**：了解客户身份和主要业务问题，提供有依据的能力介绍。

3. **方案评估**：讨论可用模块、试点方式、数据与接口条件以及需要人工核实的事项。

6. **配置与联调测试**：按确认范围建设知识、智能体或接口，并检查关键场景与异常情况。
7. **验收与上线**：按双方约定检查可用性和交付项，记录遗留事项及使用边界。
8. **后续维护与优化**：讨论知识更新、问题反馈、服务支持和变更安排。
