## 实现结果

- 接待、采购、社区组织、供应四个 Agent 通过 API 进程内的小型检索模块读取内嵌 ChromaDB；worker 仍只调度，不挂载索引。
- Markdown 源文件含来源、适用条件、Agent 白名单与主题。离线子进程构建新版本，知识清单进入 Bundle；不自动扫描更新线上索引。
- 原有技能说明与兜底保留。运行重试、交接及旧草稿使用绑定资料，不偷偷切换到最新知识。
- 查询前过滤、命中后清单/正文复核、有限结果数、超时与取消保护、单进程目录排他均已接入。
- 来源、完整知识版本与适用条件通过现有 text part 输出；未引用的资料不生成依据。
- 未提供真实 Embedding 配置或业务知识，默认保持原有 Markdown 工作方式。没有把虚构测试资料发布为真实知识。

## 实施取舍与限制

按执行过程中作出决定的顺序记录：

1. 使用固定的 `uv==0.13.5`，通过 uvx 调用，不升级全局工具；代价是首次需要下载工具与依赖。
2. 从已批准版本创建隔离工作树，避免覆盖另一任务的未提交改动；代价是后续整合原工作区时可能需要处理冲突。
3. 旧草稿的答复资料单独读取其已持久化 Bundle，执行路由与写入校验继续使用本轮运行 Bundle；增加一次受信快照读取，并保留旧草稿的旧说明。
4. 配置完整时在 API 启动阶段初始化本地 Embedding 客户端，避免 Linux 首查初始化挤占 2 秒预算；增加启动开销，不发起外部 Embedding 请求。
5. 同版本复用采用 API 退出后的离线副本校验；在线重复构建同一版本会失败，新版本仍可并行构建。
6. 真实模型召回、费用及公司事实暂不判定；配置和真实资料未提供，上线前仍需独立验收。
7. 实际发布和跨平台索引迁移不在本次执行范围；分别验证 Windows/Linux，不代表任意索引二进制都可直接跨平台搬运。
8. 不支持租户私有知识、多 API 宿主或知识管理 API；只能按当前公开资料、单宿主和文件维护方式使用。
9. 不扩大范围修复已有整库 UI/候选环境/收集问题；完整项目检查仍未全绿，整合和发布保留给后续明确操作。
